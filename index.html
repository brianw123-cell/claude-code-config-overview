Claude Code Configuration System · v3

A lean, version-controlled methodology where every session already knows how I work.

A private GitHub repo synced to ~/.claude/. A small set of preferences auto-loads every session; most files load on demand when their trigger matches. Three hooks enforce behavior. Two slash commands fire from verbal phrases. Restraint over machinery: only the parts that reliably work are in the system.

2 — How it loads

Always-on (small) vs. on-demand (most)

An earlier version auto-loaded every preference into every session, eating ~5,000 tokens before the first message. The new pattern keeps it lean by auto-loading only small universal files and triggering the bigger ones explicitly.

Always auto-load (5 files)
@user.md · @chat-context.md · @file-permissions.md · @uploaded-files.md · @minimize-prompts.md
Load on demand (read on trigger)
supabase-prefs · vercel-prefs · ux-defaults · claude-code-buildtime · security-review-prefs · google-docs-prefs/sync · voice-samples · templates/*
Trade-off: load-on-demand only works if the trigger is recognized AND the file is read before answering. To hedge, CLAUDE.md inlines the most critical numbers (build-time anchors, "Test this" requirement) so the right behavior fires even if the on-demand file gets skipped.
3 — Working modes

Four permission modes, cycled with Shift+Tab

Mostly Claude Code's defaults, not custom config. The always-ask list applies in all modes.

Read freely; prompts before every edit, write, and non-allowlisted Bash.
Accept Edits

Edits and writes without asking. Still prompts before Bash.
Auto
Mostly autonomous
Everything autonomous except the always-ask list.
Always-ask (in all modes): push to main, force-push, prod migrations, destructive ops, custom-domain deploys, real-customer email, paid-tier spend.
Truly interrupt mid-task: press Esc. Cancels the in-flight tool call. New messages typed while busy just queue — Esc is the only real interrupt.
Bypass-permissions toggle: in Claude Code app settings, "Allow bypass permissions mode" is OFF. This is correct — leaving it on would silently inject --allow-dangerously-skip-permissions into launch args and neutralize the entire allowlist.
4 — Active hooks

Three lifecycle hooks enforce behavior

Each hook has narrow gating and logs to ~/.claude/hooks/<name>.log for debugging.

SessionStart
session-start.py
If ~/.claude/.next-chat.json exists (queued by /handoff in the prior chat), injects the queued opening prompt into the new session so it immediately reads the handoff summary. Includes cwd validation. Fails silently on error — never blocks session start.
Stop
test-this-enforcer.py
If the turn edited a .tsx file under app/ or components/ but the response is missing a ## Test this section, BLOCKS the turn and tells Claude to add it. Has loop protection.
PostToolUse
ui-screenshot-reminder.py
After Edit / Write / MultiEdit on .tsx files: uses lsof to detect a running dev server for that project. If found, emits exact http://localhost:PORT/route + Claude_Preview MCP calls. If not, gives honest "skip screenshot, here's the manual npm run dev step" guidance.
5 — Commands & verbal triggers

Two commands, invoked by speaking

The user dictates and doesn't type slash syntax.

/handoff
Wrap up this chat
Writes a session summary including a "what changed and what to verify" section covering ALL change types (code / DB / deploy / env / 3rd-party). Queues an opening prompt for the next chat via .next-chat.json.
/checkpoint

Adds an entry to docs/CHECKPOINTS.md in the current project.

6 — Context monitoring

One honest rule, no theater

An earlier version had a 3-tier system tied to image counts, tool-call counts, and elapsed time. Claude can't reliably measure any of those across turns, so the tiers were aspirational. Replaced with the only thing that actually works:

Proactively offer /handoff when the user mentions slowness ("slow," "heavy," "running out," "freezing") or at a natural pause point. The verbal cue is the only reliable trigger.

13 — Permission system

Tight allow / strict ask / blanket refuse

Narrow auto-allow for known-safe categories. Hard refusal for prod migrations and credential-bearing operations.

Always-ask (no exceptions)
Push to main, force-push, prod migrations (no session approval, ever), rm -rf outside build artifacts, paid-tier spend, custom-domain deploy, real-customer email, global system packages.
JSON policy (3 tiers)
.claude/**/*.json → auto-allow (Claude's own config, no creds).
Named root configs (package, tsconfig, next, tailwind, eslint, postcss) → auto-allow.
Blanket **/*.json → refused (would match service-account.json, AWS credentials, Firebase admin keys, Stripe configs).
14 — Mac workflow

Hardware + OS context

Claude Code is the engine; local performance depends on Mac state. Long uptimes, stuck daemons, and iCloud sync churn quietly degrade everything.

Multi-monitor setup (M1 MacBook Air)

Setup: single USB-C cable to a docking station that splits to two external monitors. Reliable, no overheating, works great. Tried plugging one monitor directly to a USB-C port to bypass DisplayLink on that one (since M1 supports one native external), but the direct adapter overheated and the screen flickered. The docking station handles everything cleanly, so keep that setup.

Production deploy gotcha (logged 2026-05-30)

Vercel env vars must never have leading or trailing whitespace. Vars used in HTTP headers (CRON_SECRET, auth tokens, API keys) will fail-build with a specific Vercel error. Burned a production deploy on a client project once. vercel-prefs.md now has an xargs defensive snippet for piped env-var values.
15 — Maintenance

How the system stays current

Maintenance rule
When config changes, edit SYSTEM_OVERVIEW.md in the same commit. Bump date, add evolution log entry, update file-layout.
Commit hygiene
Commit by named file (never -A). Heredoc or file for multi-line messages. Always-ask before pushing to main.
Gitleaks pre-commit
.git/hooks/pre-commit runs gitleaks protect --staged. Blocks if it finds secrets. Reinstall on fresh clones via install-hooks.sh.
